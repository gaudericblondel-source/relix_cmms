# Relix (CMMS Web MVP) — design system (keep consistent)
- All UI in English. Target 1440×900 desktop.
- TERMINOLOGY: "Intervention" is the official name for what was called a work order (all UI text; file names WorkOrder*.dc.html, keys `wo`, ids WO-xxxx unchanged). "Failure origin" (config section `failures`), never "failure category".
- Status workflow: Requested (request not accepted yet — R-xxxx requests and interventions in Requested; Accept/Reject) → Not scheduled (accepted, no date) → Scheduled (date) → In progress → Completed (+ Rejected). collab-model FLOW/STATUS_LOOK/moveCheck (returns dialog:true for accept/schedule moves), acceptRequest(id,{date,prio}), scheduleWo, rejectRequest. AcceptRequest.dc.html (mounted in TopBar) = the one dialog: `window.RelixAccept({id,title,text,prio,mode:'later'|'schedule'|'reschedule'|'reject',onDone})`, emits `cmms-request-decided`. Board = 5 columns; pending requests show in Requested.
- Home header: secondary "Request intervention" + split primary button [+ New intervention | ⚡ Quick intervention].
- Config: `problems` (Intervention problems — tiles in RequestPanel + QuickIntervention, CFG.problems(); stored as w.problem / r.problem); spare-part categories split `partCats` (Replacement parts) / `consCats` (Consumables), CFG.itemCats(kind), allItemCats().
- App name: Relix (white logo relix-logo-white.svg). Shell: TopBar.dc.html (56px, #34050D; left Logo·Relix (23px/700); center global search Ctrl+K across equipment/WOs/parts/people/sites/locations; right Current plant selector (site switcher dropdown) · Language (UI only, `cmms.lang`) · Notifications (`cmms.notif.read`) · Profile) + Sidebar.dc.html (232px / 64px collapsed with hover tooltips, #34050D, prop `active`; collapse state in localStorage `cmms.nav.collapsed`, event `cmms-nav`; "Collapse menu" toggle at the bottom of the Sidebar; Maintenance setup click only expands/collapses its submenu, `cmms.nav.setup`). Menu: Home, Site dashboard, Assets, Work orders, Planning, Spare parts, Maintenance setup (Maintenance plans, Checklists), Documents · Teams & users, Site configuration.
- Create pattern: creating a work order anywhere opens WorkOrderPanel.dc.html (right side 560px 4-step wizard: Essentials* → Checklists → People → Details. Footer = Cancel/Previous + "Next step" (red, disabled until the step's mandatory fields are filled); "Create work order" only on the last step) via `window.CMMSCreateWO({asset})` / event `cmms-create-wo`; links to `Work Orders.dc.html?new=1` are intercepted. Emits `cmms-wo-created`.
- Quick intervention: QuickIntervention.dc.html (mounted in TopBar) via `window.CMMSQuickIntervention({asset})` / `cmms-quick`: asset (search/scan) → issue → type → Start; creates WO with quick:true ("Information incomplete") and opens Intervention.
- Collaboration: collab-model.js (window.RelixCollab) = WO store `cmms.wo.store.v1` (assignee, participants [[key, role]], checklists[], quick), people directory (handles for @mentions), chat channels (`team`, `site`, WO key) in `cmms.chat.v2`, chat notifications `cmms.notif.chat.v1` (mentions, reassignment requests, tagged WO messages only). Events `cmms-chat`, `cmms-notif`, `cmms-wo`. ChatThread.dc.html (props channel, highlight, size) is the single chat UI used in Home hub (Activity/Team/Site/Work orders), Work Order detail (Discussion) and Intervention (Chat drawer). Deep links: `Work Order…&chat=1&msg=ID`, `Home.dc.html?chat=team&msg=ID`. Page grid `auto minmax(0,1fr)`; sidebar mount `<div style="display:flex;min-height:0"><dc-import name="Sidebar" style="height:100%">`.
- Font: IBM Plex Sans (UI), IBM Plex Mono (IDs/codes). Icons: Material Symbols Outlined via font (inline `font:20px/1 'Material Symbols Outlined'`).
- Colors: accent #C00018 (primary CTA, active tab underline), bg #F6F7F9, surface #FFF, border #E4E7EC, text #1E2430, text-2 #667085, text-3 #98A2B3, success #0B6B4A, info #2456B8, warning #B54708, critical #B42318.
- Priority badges: Critical solid #C00018/#fff · High #FDECEC/#B42318 · Medium #FEF3E2/#B54708 · Low #EEF1F4/#475467.
- Status badges (dot + label): Overdue #FDECEC/#B42318 · Scheduled #EAF1FD/#2456B8 · In progress #E6F4EE/#0B6B4A · Waiting for parts #FEF3E2/#B54708 · Completed #EEF1F4/#475467.
- Panels: white, 1px #E4E7EC, radius 8, no shadow. Panel header 14px/600, "View all" link right in #C00018.
- Buttons 34px high, radius 6. Primary red; secondary white w/ border. Page title 22px/600 + 13px subtitle.
- Work orders are identified by "Asset — Task" title; the WO ID (WO-xxxx, IBM Plex Mono, #98A2B3) is shown as secondary info (lists, detail breadcrumb/copy chip, chat threads, notifications).
- Overdue items: red tinted row (#FEF6F6) + 3px #C00018 left bar + "N d late"; urgent = Critical/High priority pill with bolt icon; normal = muted priority text.
- Terminology: Work order, Maintenance plans, Checklists, Planning, Spare parts, Documents, Teams & Users, Administration.
- Intervention flow: Work Order.dc.html (detail, "Start/Resume intervention") → Intervention.dc.html (focused mode, no sidebar; one step at a time, Previous/Next, "Step N of M", Pause, Review & close). Params ?wo&task&asset&loc&type&prio&status (never `t` — preview uses it); progress in localStorage `cmms.intervention.v3.<wo>` (.summary for other pages). Row click = open WO; explicit Start/Resume button = run.
- Checklists: shared model in checklist-model.js (dynamic import; also window.CMMSChecklist; storage `cmms.checklists.v1`). Checklist Editor.dc.html = Checklist view (list, expandable StepEditor.dc.html, quick-add) + Workflow view (Start/End fixed, palette, auto-layout, drag dots to connect, + insert zones, side panel StepEditor). Intervention reads the same model; ?preview=1 uses `cmms.checklists.preview`.
- Sites: sites-model.js (organization = Business › Sub-business › Site; BUSINESSES {id,name,parent,level business|sub}, SITES with geo/tz/kpis, persisted `cmms.org.v1`, saveBusiness/saveSite/removeX, event `cmms-org`; managed ONLY in SuperAdmin.dc.html — no org/sites section in Site configuration; current site in localStorage `cmms.site`, event `cmms-site`; `cmms-site-open` opens the TopBar switcher). Site Dashboard.dc.html = tabs Overview / Work orders / Equipment / Spare parts.

- Page layout: every page fits 100vh — header (BackButton.dc.html before the title, prop fallback) + toolbars fixed; only content regions scroll (list sections scroll internally with sticky column headers).
- Notifications (deliberately simple): notif-model.js (window.RelixNotif) = 6 types assigned / request / overdue* / breakdown* / part / message (*urgent: red, pop-up stays until dismissed; others pop up 6 s); legacy keys mapped via keyOf (dropped types not shown). Prefs `cmms.notif.prefs.v2` {off:{type:true}, email}. NotificationSettings.dc.html = one list of on/off switches + 'email urgent' switch. No levels/scope/quiet hours. Smart alerts = advanced tab in NotificationSettings (maturity notif.rules L3; alerts-model.js triggers count|recurring|overdue|stopped|control|measure, evaluated by TopBar when on; notif type 'alert').
- Team chat: collab-model CHANNELS kind 'team' (team, team-leads, team-elec); Home › Teams shows only the user's teams as pills.
- Intervention: Work order chat permanently docked right (400px).
- People & skills: people-model.js (window.RelixPeople) = skills catalogue `cmms.skills.v1` (edited in Site configuration › Skills), profiles `cmms.profiles.v1` (skills [[id, level 1-3]], weekly shift per weekday + site, absences, status, bio, accent, stats), availability(), segmentsOf(checklists), suggest(), autoAssign(). Planning day 0 = Mon Sep 28 2026.
- Profiles: ProfilePanel.dc.html (mounted in TopBar + Intervention) opens on any element with `data-person="KEY|Full name"` (capture click) or `window.RelixProfile(key, {tab, edit})`. Tabs Overview / Skills / Availability; own profile + manager can edit.
- Checklist steps carry `skills[]` + `minutes` (StepEditor row); consecutive steps with the same skills form a part. AssignmentEditor.dc.html assigns one person per part (suggestions by skill + availability); WO stores `assignments [{key, skills, minutes, offset, label}]` (assignee = first). Wizard order: Essentials → Checklists → People → Details.
- Planning: backlog items have `segs [{skills, h, who}]`; dropping splits into one event per part/person; slots where nobody qualified/available are striped and refuse drops; Day view shades off-shift/absence hours.
- Plant & assets: plant-model.js (window.RelixPlant) = hierarchy Plant › Zone › Line › Step (zones MEL Melting, FOR Fiberizing & Forming, UTL Utilities, WHS Warehousing; storage areas = steps with storage:true — Spare Parts storerooms map to them by name), assets (cls fixed|mobile, loc = step id, specs [[k,v]], docs [{name,kind,size,added}]) with overrides in `cmms.assets.v1`, mobile-asset RESERVATIONS. Events `cmms-asset`, `cmms-asset-wizard`.
- AssetWizard.dc.html (create + edit, `window.RelixAssetWizard(id, {step, loc})`): Type (Equipment/Mobile + type tiles) → Location (Zone/Line/Step column drill-down + search) → Identity → Specifications → Documents. Assets.dc.html = zone cards + filter bar + "By location" accordion (Zone › Line › Step › assets) or flat list with breadcrumb. Asset Detail.dc.html?id= tabs Overview / Work orders / Documents / Reservations (mobile).
- Mobile assets: checklist steps carry `tools[]` (mobile asset ids); Planning events/backlog carry `tools`; slots where a required mobile asset is reserved are striped blue and refuse drops.

- People selection: PeopleSelect.dc.html (multi-select field; rows show avatar, name, skills, availability; props label, hint, mode assign|follow, value, onChange, exclude, skills, suggested, date). Two fields everywhere (wizard + WO edit): "Assigned users" (perform the work; assignments per checklist part derived by skill) and "Include in follow-up" (not assigned; chat + updates; participants role 'Follow-up'). Never "Participants".
- Required spare parts: checklist 'parts' steps carry parts [{ref, qty}]; CL.partsOf(cls) aggregates. Selecting checklists auto-adds them (tag "From checklist"); user can add more or remove (removed refs tracked in dismissed, restorable).
- QuickIntervention uses the same right-side panel shell as WorkOrderPanel (header tile, step bar, 44px fields, footer Cancel/Previous + Next step → Start intervention). 2 steps: Equipment → Issue.
- Assets.dc.html: three views (localStorage cmms.assets.view, ?view=list|tree|map): List = flat asset list with zone cards + filters; Hierarchy (tree) = original org-chart (left searchable tree + node chart Plant › Zone › Line › Step › Asset, zoom, selected-node card); Plant layout (map) = left accordion + box map, to be fitted later onto the real plant layout drawing.
- Site configuration: config-model.js (window.RelixConfig, `cmms.config.v1`, event `cmms-config`) = sections assetTypes, crit, woTypes, failures, prio, status, partCats, costCenters, customFields, labels, quantities, sites + per-site units (siteUnits/unitFor). Administration.dc.html = schema-driven CRUD (drawer form, delete confirm with usage check, activate toggle, restore defaults); Plant hierarchy edits via plant-model saveNode/removeNode (`cmms.plant.v1`); skills via people-model; sites override sites-model.
- Custom fields: fieldsFor(entity,{type}), fieldUnit (quantity → site unit), validate, fmt. Used in AssetWizard (Specifications), WorkOrderPanel (Details), Work Order edit/detail, Spare parts form/detail. Records store `custom {key: value}`; cost centers stored as `costCenter` code on parts/assets/WOs.
- Spare parts & suppliers: parts-model.js (window.RelixParts, `cmms.parts.v2`, `cmms.suppliers.v1`): parts have ref, code (item/article), gtin (validated check digit), image (resized data URL), supplier id, supplierRef, costCenter, assets[] (linked equipment), store = plant storage step id, custom. Suppliers.dc.html (Sidebar below Teams & users).
- Required equipment: WOs store `tools[]` (auto from checklists, editable); plant-model toolConflicts/nextFreeSlot/reserve (`cmms.reservations.v1`). WorkOrderPanel Details + Work Order edit block saving/creating while a required mobile asset is reserved at the chosen time; Planning refuses drops on WO-created reservations.
- Chat: ChatThread mounts must be wrapped `<div style="position:relative;flex:1;min-height:0"><dc-import name="ChatThread" style="position:absolute;inset:0">`. Direct messages: channels `dm-<KEY>` (collab-model isDm, dmThreads, sharedWith); Home hub tab "Direct" groups conversations per person ("All together" view). Deep link Home.dc.html?chat=dm-MD.
- Home To-do: no checkbox; action column = Start / Resume / Completed (non-clickable) / Waiting.- Advanced features (in development, shown in purple #800080; AI features carry a white "AI" badge in the button): switched per feature in the maturity catalogue (legacy flag `cmms.advanced` forced '1'). Pages expose `advVals()` (adv + handlers). advanced-model.js = lifecycleOf / obsolescenceOf (risk score) / contractsOf / liveOf (simulated PLC·EMS·CMS feed). AdvancedPanel.dc.html (mounted in TopBar, `window.RelixAdvanced(k, ctx)`): optimize (Planning), forecast (Spare parts), checklist (Checklists, generate from document → saves draft + opens ChecklistEditor), plan (Maintenance plans, from manufacturer manual), diagnose (Asset live tab), fleet (Assets "Lifecycle & risk"). AssetAdvanced.dc.html (props view lifecycle|live, assetId) = AssetDetail tabs Lifecycle / Live monitoring (`?tab=`).
- Item types (Spare parts module = single source of truth, parts-model.js): kind 'part' (Replacement part, whole units, icon settings, grey) | 'consumable' (icon water_drop, teal #0E7490 / #E3F2F6). Consumables: usage 'amount' (in stock unit or useUnit sub-unit mL/g/cm, converted) or 'percent' (% of one unit; stock fractional, shown "3 rolls + 1 opened (65%)"). Helpers usageOf / toStock / fmtUse / fmtStock / costOfUse / consume(ref, amount, wo). UsageInput.dc.html (props itemRef, value, onChange, size sm|lg) = the one adaptive input (stepper / amount / slider) used in StepEditor, Intervention, WorkOrderPanel. checklist-model CATALOG is a live view of parts-model; partsOf aggregates 'parts' + 'consumables' steps. cost-model prices actual usage (consumables from WO parts/used → Consumables line). Intervention completion stores wo.used and deducts stock once (stockDone). SpareParts.dc.html: type filter (All / Replacement parts / Consumables, ?kind=), Item type + usage config in form.
- Maintenance plans: plans-model.js (window.RelixPlans, `cmms.plans.v1`, event `cmms-plans`, TODAY 2026-09-29): nextDue (calendar / meter via plant-model meterOf), generate(id) writes preventive WOs (planId, generatedBy) to the WO store + 'plan-due' notification; runDue() is called by TopBar on every page (lead time per plan); reminders() = inspection / calibration plans (Home carousel "Reminders"). Planning loads stored WOs on mount.
- Meters: plant-model meterOf / addReading (`cmms.meters.v1`); Asset Detail › Preventive tab. Assets carry photo (data URL), commissioned, decommissioned {reason,date,note}, history[] (auto in saveAsset); removeAsset.
- AssetActions.dc.html (mounted in TopBar): `window.RelixAssetActions(kind, ids, extra)` kind qr | decommission | delete | import. qr-util.js = real QR (qrcode-generator CDN) encoding AssetDetail URL, PNG download, label formats 50×25 / 70×35 / 100×50 / A4.
- Pager.dc.html (props total, page, size, onPage, onSize, noun) = pagination footer on every list (sticky bottom).
- WO history: collab-model saveWo appends history[] for status/priority/assignee/due/waiting/type/title changes; WorkOrder "History" section; root cause analysis (w.rca) on corrective WOs. collab-model notify(n) for generic notifications.
- SignIn.dc.html (index.html → sign in → Main). TopBar "?" help menu. Documents category "Plan" (was Drawing). WorkOrderPanel Details: Request date* (back-dating), Description*, date checks, "Create another".
- Maturity: maturity-model.js (window.RelixMaturity, `cmms.maturity.v1` per site {levels (baseline), over}, event `cmms-maturity`) = 10 concepts + FEATURES catalogue (id, concept, level 1 Essential/2 Intermediate/3 Expert, core, req, ai). on(id) = override ?? level ≥ feature level, and req on; setFeature auto-enables req. MaturityLevels.dc.html (Administration › Site profile) = feature catalogue only (no By-level mode): summary Feature level vs Actual maturity (/5) + "Analyze my site" recommendations (maturity-insights.js: featureLevel, maturity from usage signals, analyze → activate/deactivate/explore, apply/ignore, `cmms.maturity.recos.v1`), left module nav, per-feature switches; Advanced (ai, purple #800080) features are toggled per feature — no global Advanced switch (cmms.advanced kept '1'). Actual maturity ≥ 4.5 → inline "Want to go further?" idea input (cmms.ideas.v1). Gating: model injects `<style id=relix-maturity>` hiding `[data-feature~=id]`; pages use `FON(id)` in renderVals (+ cmms-maturity re-render); Sidebar hides modules (pageFeature); TopBar overlays switched-off pages. New UI for a catalogued feature must carry data-feature or FON().
- Maturity principles: levels change complexity, never availability of fundamentals (checklists on interventions are core at L1); gating hides UI only, never data — fields holding a value stay visible; Intervention executes every existing checklist step whatever the level (authoring gated, execution not). Optional fields = progressive "+ Label" chips (WorkOrderPanel Details "Add if needed"; StepEditor per-option chips, no "More options"). Key flags: wo.chat L1 = discussion + "Include in follow-up" (old wo.followup aliased); cl.media L1 core; plan.module core; prev.cbm L3 (cbm-model.js measurement points, Asset › Preventive); notif.rules L3; 30/30 → "Want to go further?" idea box (cmms.ideas.v1). wo.fields (failure origin, custom fields) / wo.history L2, wo.strict L3 (description+request date+failure origin default, description required), wo.costs L3 (cost card, cost center, external services); cl.types L2 (beyond basic steps yesno/number/comment/instruction/confirm/photo), cl.workflow L3 (branching, Then/After/Branch only, Workflow view); assets.import L1; parts.consumables/suppliers L2. Wizard has "Create now" after Essentials. Administration sections gated via SEC_FEAT.

- Access: access-model.js (window.RelixAccess) = users `cmms.users.v1` (role id, sites[], siteRoles {SITE: roleId}, financial, superAdmin, rate €/h, status), teams `cmms.teams.v1` (members = user ids, lead, icon, color; collab-model team CHANNELS + person().team are derived from them), roles & matrix `cmms.roles.v1` (modules assets, workorders, plans, planning, parts, suppliers, documents, teams, admin × F/E/V/-; Administrator locked Full), super-user scopes `cmms.superusers.v1` (business | sub | country | sites + role; dynamic). can(module, need), canFinance(), rateOf(key), sitesFor(), adminsOf(site). Event `cmms-access`. Signed-in user GD; "Preview access as" (profile menu, `cmms.preview-as`) shows what another user sees.
- Enforcement: Sidebar hides modules with None; TopBar guard overlays pages with None ("No access"), View = "View only" chip + hides the red header create button; site switcher lists sitesFor(); WorkOrderPanel refuses creation without Work orders Edit.
- Financial (cumulative permission): without it, cost-model / parts-model / advanced-model / config-model formatters return "•••"; WOCosts shows a locked card; hourly rates, cost fields, supplier rates and budgets are hidden. Labor cost = user hourly rate (Teams & users) × hours.
- Home: Intervention requests block hidden when nothing to review; hub = Activity + Chat (one unified conversation list: direct, teams, site, work orders; search + Unread filter; thread view per conversation); Not scheduled = horizontal compact cards with calendar icon (opens slot dialog); scheduled to-do items are individual cards.

- KPI strips: separate cards (gap 12, white, 1px border, radius 8) with 36px colored icon tile + label + value + sub; tone/icon via KDECO(label) helper in each page (crit/warn/ok/info/neutral); selected = red border + #FBF7F7.
- Home: no period/zone header controls; To-do has one "Filter" dropdown (type, priority, status, zone, hide completed); Not scheduled block hidden when empty; Analytics hidden entirely when collapsed, reopened from an "Analytics" button in the Activity/Chat header.
- Interventions board: no legend, fits the page (columns scroll internally); board has no Status select (Overdue / Flagged waiting in More filters). Header = Request intervention + split [New intervention | ⚡].
- Assets Hierarchy / Plant layout: drag to pan, Ctrl/⌘ + wheel zoom (native non-passive listeners, attachPan helper).
- Autonomous maintenance: am-model.js (window.RelixAM, `cmms.am.v1`, event `cmms-am`) standards {line, task, days, slots[] (several rounds per day), by, mins}; Planning › Autonomous track = week grid with one chip per round, day drawer, record Done / Anomaly (creates request) / Missed, New/Edit standard.
