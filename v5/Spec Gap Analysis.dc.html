Done in the Oct 7 pass

  • Preventive engine: shared plans model, automatic work-order generation with lead time, meter readings, “Preventive due soon” notifications (§13, §11, §17)
  • Asset sheet: photo, commissioning date, Preventive and History tabs, indicators, decommission / delete, real QR with PNG and label formats (§6, §8)
  • Asset list: status KPIs, selection, row menu, export, bulk QR, import with mapping and validation (§5, §7)
  • Pagination on every list; “?” help icon; sign-in screen (§2, §4)
  • Home: last update, period selector, filters, calibration / control reminders (§4)
  • Work orders: In progress KPI, request date, mandatory description, date checks, “Create another”, history trail, root cause analysis (§9, §10, §19)
  • Alert rules per asset scope / owner / zone with recurring-failure detection (§17)
  • Oct 12: condition-based maintenance — measurement points, limits, automatic interventions (§1); Smart alerts restored with a “more than N interventions” trigger (§17)

Still missing

  • Type › Sub-type taxonomy, Palliative sub-type, Opportunistic sub-type (§1) — taxonomy left out of this pass
  • FMEA and an RCA record grouping several work orders (§1)
  • Home: operational KPI set, priority alert cards, “My planning” tab (§4)
  • 5-level asset breakdown Machine › Sub-assembly › Component (§5)
  • Team (pool) assignment on work orders (§11.1); context KPIs on Plans (§3.2)

Decisions pending with the spec authors

  • Work orders called “Interventions” (§2.1) and the “Preventive” menu label
  • Overdue / Waiting for parts as statuses — Relix shows them as badges, filters and KPIs (§9)
  • Mandatory assignee at creation (§10); one form vs. the 4-step wizard
  • Spare parts in the MVP (§4); typed / branching checklists (§12); notification centre (§21)
  • Permission matrix to validate (§15); autonomous maintenance as rounds, not work orders (§1)

Priorities

  1. Settle the open decisions with the spec authors — vocabulary, status model, mandatory assignee, Spare parts scope, checklist scope, notification centre, permission matrix.
  2. Type › Sub-type taxonomy — unlocks Palliative → curative follow-up and Opportunistic work grouped on planned shutdowns.
  3. Fix the asset hierarchy depth (5 levels) — the import format and QR labels already exist and will follow.
  4. Home operational layer — KPI set and priority alert cards on top of the reminders now in place.
  5. Condition-based maintenance — measurement points and thresholds on top of the new meter readings.
